# MeetCam: license and IP audit

Date: 2026-10-30. Everything fetched from the web was fetched on this date.

**Scope.** The repository (then named MeetCam, private; `LICENSE` is the plain GPL-3.0 text). Audited before the commit that replaced the anime terms and real people's names with generic ones; that commit was made while this audit ran, so section 7 describes both states. Commit hashes are not quoted: the history was rewritten afterwards. Environment audited: the project's `.venv` on Windows 11 x64, CPython 3.12.10, 35 installed distributions enumerated with `importlib.metadata`. **macOS and Linux wheels were not inspected**; they bundle different native libraries (for example OpenCV's Linux/macOS wheels carry Qt 5, GnuTLS and others, see `SP/cv2/LICENSE-3RD-PARTY.txt`).

**Method.** Primary sources only: installed license files and metadata (`SP` below means `.venv/Lib/site-packages`), strings extracted from the installed binaries, upstream repositories read through the GitHub API, official vendor pages, FSF pages (downloaded and parsed locally), official law texts, and one live network probe. Where a claim could not be confirmed it is marked **unverified**. Quotations are avoided on purpose; sources are paraphrased and cited.

## 1. Summary

Severity: **BLOCKER** (stops a bundled-installer release), **SHOULD FIX** (before the public release), **NOTE**.

1. **BLOCKER for installers (document it now): pyvirtualcam 0.15.0 is GPL-2.0 with no "or later" grant, so treat it as GPL-2.0-only.** The installed license file is the plain GPLv2 text, the PyPI classifier is GPLv2, the maintainer's own files carry no license header, and the maintainer states in issue #4 that the project is GPL-2 because it bundles OBS-derived code. Per the FSF, GPLv2-only is incompatible with GPLv3, and Apache-2.0 is incompatible with GPLv2, yet MeetCam imports pyvirtualcam in the same process as Apache-2.0 MediaPipe and OpenCV. A source-only repo conveys none of it, so nothing is breached today; an installer containing all of them would have no license that satisfies every component. Options and trade-offs in section 3 (ask upstream for "or later", helper process, own writer, OBS as sink, user-installed).
2. **SHOULD FIX: MediaPipe 1.0.1 contacts Google and its NOTICE puts consent on the app developer.** The NOTICE (modified 2026-06-05) and Google's page say Tasks APIs send performance/usage metrics to Google and that you must obtain informed consent from your users; no opt-out is documented. Observed here: closing a `HandLandmarker` opened one HTTPS connection to Google-owned address space (2001:4860::/32); the TLS payload was not inspected. Needs a README and first-run disclosure plus a decision on mitigation (section 5.2).
3. **SHOULD FIX: MeetCam's own legal metadata is missing.** No copyright holder or year anywhere, no per-file notices or SPDX tags, "GPL-3.0 only" vs "or later" is not stated (GPLv3 section 14 then lets recipients pick any version), no About / Legal Notices screen (GPLv3 section 5(d)), no third-party notices file, no credits in the README. Decide the contribution policy (DCO or CLA) **before** accepting outside pull requests if you want to keep the freedom to change the license later (relevant to item 1).
4. **SHOULD FIX before installers: bundling checklist.** Ship all license texts, MediaPipe's NOTICE, and OpenCV's `LICENSE-3RD-PARTY.txt` (it carries the Intel IPP terms). LGPL parts (Qt 6.12 and FFmpeg 9.0.1 inside PySide6; a second FFmpeg, libavformat 61.7.100, inside OpenCV; libsndfile 1.2.2 with mpg123 and LAME) need unrenamed, replaceable DLLs (PyInstaller one-folder, no UPX), a source link or written offer, and an about-box line. Leave out Qt WebEngine (Chromium, installed but unused) and the PortAudio ASIO DLLs. Microsoft limits redistribution of the Visual C++ runtime DLLs to licensed Visual Studio users, so prefer Microsoft's own redistributable installer as a prerequisite (section 4b).
5. **SHOULD FIX (clearance needed): the name "MeetCam" is already in use by other products.** An Android app "Meetcam - Video Chat & Live" (developer Codder Lab Limited, `com.meetcam.app`) and a web video-chat service at meetcam.tv ("Meetcamtv"). Near-miss marks (MECAM, ME2CAM, METACAM) appear in USPTO aggregators. No exact MEETCAM registration surfaced through search engines, but the official registries cannot be queried non-interactively, so this is not a clearance (section 9).
6. **NOTE: VB-CABLE and OBS.** VB-CABLE is donationware. VB-Audio's own licensing page allows shipping the VB-CABLE package with an application, even a silent install inside your installer, if users can see it is a VB-Audio donationware product and you display the origin and donationware lines; professional or company use needs paid licenses. The README's current approach (user installs it from vb-audio.com) is the one VB-Audio itself describes as simplest. OBS Studio is GPL-2.0-or-later: redistributable under the GPL, but the installer is about 158 MB and carries its own GPL/LGPL stack (x264, Qt, FFmpeg), so it is a heavy thing to take on; no OBS trademark policy was found (section 6).
7. **NOTE: third-party product names.** Use plain-text, factual mentions of Google Meet, Zoom, Windows, OBS and VB-CABLE; no logos, icons, brand colours or fonts; add a "not affiliated" line. Zoom's developer rules forbid "Zoom" inside a product name ("for Zoom" is allowed there); Google asks for approval before its logos or product visuals are used for compatibility or entertainment purposes (section 7.1).
8. **NOTE: anime and real-person names.** At the start of this audit the app used "Rasengan" and "Kage Bunshin" as default names and the notes mentioned a sound named after an Indonesian politician; the generic-names commit genericized the user-facing text, but the old names remain in git history and `jutsu.py` is still a module name. a 2011 WIPO decision records Shueisha as holder of NARUTO registrations in the US and Canada (current status unverified); no RASENGAN registration was found (unverified); bare names are not copyrightable but can be trademarks. For real people, the primary-text hooks are Indonesia's ITE Law art. 27A / 45(4)-(5) and the Copyright Law art. 12 on portraits; foreign right-of-publicity laws were not researched (section 7.2, 7.3).
9. **NOTE: AI-assisted authorship.** Anthropic assigns whatever rights it has in Outputs to you (Consumer Terms section 4; Commercial Terms section B), without promising that Outputs are copyrightable or non-infringing. The US Copyright Office says AI-assisted works are protected only for their human-authored expression and that prompts alone are not enough. GPL-3.0 can still be applied to the repo as a whole (it bites on the protectable parts). Disclose the AI assistance in the README (60 of the first 68 commits already carry a Claude co-author trailer) and keep the specs and decision notes as evidence of human direction (section 8).
10. **NOTE: the hand landmarker model may be bundled.** Google's model card for the hand tracking models lists Apache License 2.0. Bundling needs the license text and attribution only. Today's "user downloads it" flow is also fine. If bundled, pin by hash: the local copy is 7,819,105 bytes, sha256 `fbc2a30080c3c557093b5ddfc334698132eb341044ccee322ccf8bcf3607cde1` (section 5.1).

### 3.2 Consequences (FSF positions; not court-tested for Python imports, **unverified**)

- **GPLv3 vs GPLv2-only:** not compatible; combining them would violate section 6 of GPLv2 (FAQ #v2v3Compatibility; license list #GPLv2). Code released as "v2 or later" is compatible because v3 is one of its options.
- **Apache-2.0 vs GPLv2:** not compatible (patent termination and indemnification terms); compatible with GPLv3 (license list #apache2). MediaPipe and OpenCV are both Apache-2.0 hard dependencies (mediapipe itself requires opencv-contrib-python).
- **In-process use is a combination:** a program that links a GPL library must be under the GPL as a whole (FAQ #IfLibraryIsGPL, #GPLStaticVsDynamic); dynamically loaded modules that call each other and share data count as one program (FAQ #GPLPlugins); shared memory carrying complex structures is treated as roughly equivalent to dynamic linking. By contrast pipes, sockets and command-line arguments are normally communication between separate programs unless the exchanged data is intimate (FAQ #MereAggregation); the FSF says the boundary is ultimately a question for judges.
- **Today (source-only):** the repo conveys none of pyvirtualcam, MediaPipe or OpenCV; users assemble the combination privately on their own machines, which is not conveying. So the repo itself breaches nothing. It does state GPL-3.0 for a program that, on the FSF's reading, cannot be GPL-3.0 once it imports a GPLv2-only module, and anyone who repackages it inherits the problem.
- **Installer (later):** one bundle with MeetCam + pyvirtualcam + MediaPipe + OpenCV has no license under which it can be conveyed if pyvirtualcam stays v2-only: GPLv3 for the Apache parts conflicts with GPLv2-only, and GPLv2 for pyvirtualcam conflicts with the Apache terms.

Dependencies come from PyPI at install time. The model file and all media are git-ignored. So **no dependency license imposes anything on the repo itself.**
- What does apply is MeetCam's own license hygiene: add `Copyright (C) <year> <holder>`; say whether it is GPL-3.0-only or GPL-3.0-or-later (GPLv3 section 14: if no version is specified, recipients may choose any); optional SPDX tags (`GPL-3.0-only` or `GPL-3.0-or-later`); an in-app "Appropriate Legal Notices" feature (copyright, no warranty, license, how to read it; GPLv3 sections 0 and 5(d)); README credits (Appendix A).

### 4b. Bundled installers (later)

- **Tooling.** PyInstaller itself is GPL-2.0-or-later with a Bootloader Exception that lets you distribute the embedded bootloader inside any combination; its run-time hooks are Apache-2.0 (https://github.com/pyinstaller/pyinstaller/blob/develop/COPYING.txt). The FSF says an installer and the files it installs are separate works, so the installer tool's license does not matter (FAQ #GPLCompatInstaller).
- **MeetCam (GPL-3.0).** Provide the Corresponding Source for the exact version: tagged source plus the build scripts (PyInstaller spec, installer script, lock file). Hosting source next to the binaries satisfies section 6(d); the source may sit on a different server if you give clear directions and keep it available as long as you distribute binaries (FAQ #SourceAndBinaryOnDifferentSites). Ship the GPL-3.0 text.
- **LGPL parts** (Qt/PySide6; FFmpeg 9.0.1 in PySide6; FFmpeg libavformat 61.7.100 in OpenCV; libsndfile 1.2.2 with mpg123 and LAME): ship the license texts; keep the libraries as separate DLL files (PyInstaller one-folder layout; no UPX; no renaming or obfuscation), so users can replace them; offer or host the matching source. Qt's own page says the complete corresponding source must be delivered even for unmodified libraries and that users must be able to relink. Because MeetCam itself is GPL-3.0 and fully open, rebuilding the bundle with a different Qt or FFmpeg is possible for any recipient. Source pointers to collect: Qt 6.12.0 and PySide6 6.12.0; FFmpeg 9.0.1 with the configure line printed from the DLL (`--disable-programs --enable-shared --disable-static --toolchain=msvc ...`); the OpenCV FFmpeg source (libavformat 61.7.100, which I infer to be the FFmpeg 7.1 series) with its configure line (`--enable-libopenh264 --enable-libvpx --enable-libaom --disable-filters ...`); libsndfile 1.2.2 plus mpg123, LAME and the Xiph libraries.
- **FFmpeg checklist (ffmpeg.org/legal.html).** No `--enable-gpl` or nonfree, dynamic linking, source hosted next to the binary with an exact match, an about-box line saying the software uses libraries from the FFmpeg project under the LGPLv2.1, no EULA clause forbidding reverse engineering, spell "FFmpeg" correctly, do not rename the DLLs. Its patent mini-FAQ says FFmpeg offers no patent license and the owners of H.264 / MPEG-4 patents may seek fees from commercial products; MeetCam decodes the user's own media only (no encoding), and I did not research the position for free software (**unverified**).
- **Qt Multimedia backend.** Windows uses the FFmpeg backend by default; the older Windows Media Foundation backend is deprecated since Qt 6.10 and can be selected with the environment variable `QT_MEDIA_BACKEND=windows` (https://doc.qt.io/qt-6/qtmultimedia-index.html). That would avoid shipping Qt's FFmpeg but ties you to a deprecated backend (trade-off, not advice).
- **Apache-2.0 parts** (MediaPipe, OpenCV, absl-py, flatbuffers, the model): give recipients the license (section 4(a)); keep copyright, patent and attribution notices (4(c)); carry the NOTICE attributions (4(d)); mark changes if you modify anything (4(b)).
- **BSD / MIT / PSF / HPND parts:** reproduce copyright and license text in the documentation or About screen. Credit lines that are explicitly required: FreeType Team (FTL), Independent JPEG Group (IJG), plus the BSD-3 "no endorsement" clauses (do not use contributors' names to promote MeetCam).
- **MPL-2.0 (certifi):** ship the MPL text and distribute the CA bundle unmodified.
- **Proprietary-term items inside wheels.** Intel IPP ICV (inside `cv2.pyd`): keep the notice and the binary unmodified. Microsoft's Visual C++ runtime DLLs (copies sit in `numpy.libs`, `shiboken6`, Python itself): Microsoft's page says distribution of the runtime package, merge modules and individual binaries is limited to licensed Visual Studio users and subject to its license terms (https://learn.microsoft.com/en-us/cpp/windows/redistributing-visual-cpp-files); the recommended route is to run Microsoft's own redistributable installer as a prerequisite.
- **Optional hardening.** The FSF suggests that the copyright holder of a GPL program can add an explicit linking permission for GPL-incompatible libraries (FAQ #GPLIncompatibleLibs; GPLv3 section 7 template). Considering the Intel IPP binary and the advertising-clause entries in MediaPipe's NOTICE, such a permission in MeetCam's license notice would cover downstream redistributors. It cannot fix pyvirtualcam, because only pyvirtualcam's copyright holders can change its terms.
- **Exclude** Qt WebEngine / Chromium, Qt Pdf, Qt 3D / Quick / Charts and other unused Qt modules (some are GPL-only), the PortAudio `*-asio.dll` and other-architecture DLLs, matplotlib test data, and pytest.
- **App stores.** Whether Apple's or Microsoft's store terms fit GPL-3.0 was not researched (listed in section 10); direct downloads from the project's own release page are what this audit assumes.

Google's page repeats it and describes no opt-out (https://developers.google.com/edge/mediapipe/solutions/tasks, section "MediaPipe Tasks Privacy Notice"; short link goo.gle/mediapipe-privacy). Apache-2.0 section 4 has recipients receive the license and keeps attribution notices, and section 4(d) has derivative works you distribute carry the NOTICE attributions; shipping the NOTICE file unchanged is the simple way to meet both, and it carries this privacy text with it.
- **In the binary.** `mediapipe/tasks/c/libmediapipe.dll` contains Google Clearcut logging-client code (symbols such as `ClearcutLoggingClient` in `mediapipe::tasks::core::logging` and `PortableClearcutUploader`); the Python wrapper tells the library its host environment is Python (`base_options.py`).
- **Observed behavior (two valid runs, this machine, Windows).** A script created a `HandLandmarker` with the local model and ran it on blank frames. No outbound connection was seen during 20 to 40 s of detection or during 25 s idle. Within about 0.3 s after `HandLandmarker.close()` started, one TCP connection to `[2001:4860:4841:400::]:443` appeared. ARIN RDAP lists 2001:4860::/32 as GOOGLE-IPV6, registrant Google LLC (https://rdap.arin.net/registry/ip/2001:4860:4841:400::). The payload is TLS; **its content was not inspected**, so "usage metrics only" is the vendor's claim, not verified here. A first attempt polled the wrong PID (the venv launcher) and was discarded. Whether MeetCam closes the tracker on every exit path, and how often it re-creates it, was not examined.
- **What it means.** Every session end (or tracker restart) probably contacts Google. If MeetCam is published, the NOTICE puts the consent duty on you as the app developer.
- **Options (neutral).** (1) Disclose in the README and with a first-run notice that hand tracking runs locally but MediaPipe may send usage metrics to Google. (2) Capture actual traffic with a proxy or packet capture to document exactly what is sent. (3) Offer an off switch you control (for example a firewall rule per executable; effect on MediaPipe behavior **unverified**). (4) Replace MediaPipe Tasks with another runtime for the same Apache-2.0 TFLite models (large engineering effort; **feasibility unverified**). (5) Test other MediaPipe versions for the same behavior (not done; **unverified** whether older versions behave differently).

## 8. Item 5: AI-assisted authorship

### 8.1 Who owns the output (Anthropic)

- Which terms apply: Claude Code is governed by the Consumer Terms for Free, Pro and Max users and by the Commercial Terms for Team, Enterprise and API users (https://code.claude.com/docs/en/legal-and-compliance). The plan used for this project is **unknown**.
- Consumer Terms (effective Oct 8, 2025, as shown on 2026-10-30), section 4: you keep the rights you have in your Inputs; for Outputs Anthropic says "we assign to you all of our right, title, and interest—if any—in Outputs", conditioned on your compliance with the Terms (https://www.anthropic.com/legal/consumer-terms).
- Commercial Terms, section B: the customer retains its Inputs and owns its Outputs, and Anthropic assigns its right, title and interest (if any) in Outputs; section K.1 adds an IP indemnity for paid use of the services and Outputs generated through it (https://www.anthropic.com/legal/commercial-terms). I did not find an IP indemnity in the Consumer Terms text I retrieved (**unverified**).
- Both assign only what Anthropic has, and neither promises that Outputs are protectable or free of third-party rights. Usage is also subject to Anthropic's Usage Policy (https://www.anthropic.com/legal/aup); I found nothing in the pages above restricting open-source release of generated code, but did not read the policy in full (**unverified**).

### 8.2 Copyrightability (US Copyright Office)

- 2023 registration guidance, 88 Fed. Reg. 16190 (Mar. 16, 2023): copyright protects only human authorship; when a tool receives only a prompt and produces the expressive elements, that material is not protected and must be disclaimed in a registration; AI-generated content that is more than minimal must be explicitly excluded; applicants must disclose it and briefly describe the human contribution; a human's selection and arrangement, or modifications of AI output, can be protected; do not list the AI or its vendor as an author (https://www.govinfo.gov/content/pkg/FR-2023-03-16/pdf/2023-05321.pdf).
- Report "Copyright and Artificial Intelligence, Part 2: Copyrightability" (Jan. 29, 2025): using AI to assist rather than replace human creativity does not affect protection; copyright covers the human-authored expression even when AI material is present; it does not cover purely AI-generated material or material with insufficient human control; on today's technology, prompts alone do not give sufficient control; human authors keep rights in their own perceptible expression, in creative selection, coordination or arrangement, and in creative modifications; analysis is case by case (https://www.copyright.gov/ai/Copyright-and-Artificial-Intelligence-Part-2-Copyrightability-Report.pdf). The report notes that programmers already use automated tools for refactoring and translating code.
- Indonesia: Law 28/2014 art. 1(2) defines an author as a person (or persons) who produce a distinctive and personal creation. I found no Indonesian authority specifically on AI-assisted works (**unverified**).

### 8.3 What it means for GPL-3.0 and the README

- GPL-3.0 is a copyright license; it works on whatever in the repo is protected (human-authored code, selection and arrangement, documents the owner wrote or substantially edited). AI-generated parts that lack protection cannot be licensed or enforced, and anyone could reuse them regardless of the GPL, at least in the US. Applying GPL-3.0 to the whole repository is still the normal and harmless course; the copyright notice should name the human owner.
- A `Co-Authored-By: Claude ...` trailer (present on 60 of 68 commits) records tooling; per the Copyright Office guidance an AI is not listed as an author, so the trailer does not create a claim by anyone else (Anthropic's terms assign its rights to you anyway).
- Recommended disclosure: one README sentence that the code was written with AI assistance (Claude Code) under the owner's direction. It is not required for an open-source release; it would be required in a US copyright registration application.
- Keep evidence of human creative control: the dated specs and plans under `docs/superpowers/`, `DECISIONS.md`, hand edits, test design.
- Third-party-content risk in generated code is not eliminated by ownership terms; a similarity / license scan before a 1.0 release is an optional safeguard (no tool was run).

## Appendix B. Reproducing the key local checks

- Enumerate installed licenses: `.venv/Scripts/python -I -c "import importlib.metadata as m; [print(d.metadata['Name'], d.version, d.metadata.get('License-Expression') or d.metadata.get('License')) for d in m.distributions()]"`.
- FFmpeg license in a DLL: extract printable strings and look for the "license:" and configure lines (`SP/PySide6/avutil-61.dll`, `SP/cv2/opencv_videoio_ffmpeg500_64.dll`).
- Telemetry probe: run a `HandLandmarker` on blank frames from the venv, poll `Get-NetTCPConnection -OwningProcess <real python PID>` (the venv's `python.exe` is a launcher; use its child process), and print wall-clock markers around `close()`.
- Law texts: `peraturan.bpk.go.id` PDFs linked in section 7.3 converted with `pdftotext`.

## Follow-up decisions (2026-10-30, after this audit)

- **Name.** Renamed to **Meetru** ("Meeting Seru"). A web search and a GitHub search found no product, company or repository named exactly "Meetru" (near names exist: Meetruly, MeetRun, MeetRunning, MeetrumRecorder). Not a trademark clearance: USPTO, EUIPO, WIPO and DJKI were not queried.
- **License.** GPL-3.0-or-later (SPDX header and copyright line in every `.py` file; checked by `tests/test_license_headers.py`).
- **In-app notices.** `legal.py`: a notice before the first start about MediaPipe's usage metrics (Continue or Quit; Quit means the camera never starts) and an About box (F1) with the GPL notices, the license text, the libraries and the trademark lines (item 3 and the GPLv3 5(d) point above).
- **Contributions.** DCO sign-off (`CONTRIBUTING.md`, `DCO`).
- **pyvirtualcam removed.** Replaced by Meetru's own writer for the OBS Virtual Camera (`virtualcam.py`, Windows): written from OBS Studio's shared-memory queue format (GPL-2.0-or-later) with no pyvirtualcam code or dependency. Checked against the real OBS DirectShow camera (colours, orientation and grey ramp match the source; pyvirtualcam's own output deviated more).
- **History.** The project moved to a new repository (`lfarabi/meetru`) built from a rewritten history: the anime terms, the real people's names, a downloader's file tag and the author's personal email address are gone from every commit and message. The earlier repository stays private and is not part of this project's public history.
- **Still open.** The official trademark searches; virtual-camera writers for macOS and Linux; installers (sub-project 2).
